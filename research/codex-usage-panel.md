## 1. Executive summary: Codex has **three** distinct usage surfaces

The request "completely imitate the Codex profile panel that displays token usage" is ambiguous because Codex ships three different surfaces. They must not be conflated.

| # | Surface | Opened by | What it is | Priority for DSH |
|---|---|---|---|---|
| **A** | **`/status` card** | `/status` | An inline scrollback card. The session/profile panel: model, directory, permissions, **token usage**, context window, rate-limit windows, credits. | **Primary** — this is "the profile panel with token usage". |
| **B** | **`/usage` menu → analytics panel** | `/usage` (bare) opens a 2-item menu; `/usage daily\|weekly\|cumulative` opens the chart directly; "View analytics" opens the full-screen dashboard | A full-screen alternate-screen app with tabs `Overview / Credits / Tokens / Messages / Plugins / Skills / Chats`. | Secondary — the "account usage" page. |
| **C** | **Statusline (composer footer)** | `/statusline` (configures which items appear) | One-line inline strip of opt-in items: model · context · limits · tokens. | High value, cheapest to copy. |

`CONFIRMED`: `/status` description string is *"show current session configuration and token usage"*; `/usage` is *"view account usage or use a usage limit reset"* — [`codex-rs/tui/src/slash_command.rs#L119-L122`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/slash_command.rs#L119).

There is **no `/profile` slash command** in the open-source tree. The closest thing is the analytics `Overview` tab, whose source file is literally named `summary_panel.rs` and whose module doc reads *"Responsive **profile** summary using the Analytics container's typography and spacing."* (`CONFIRMED`, [`analytics/summary_panel.rs#L1`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/analytics/summary_panel.rs#L1)). That is almost certainly the "profile panel" the user means.

**No IDE/VS Code extension exists in this repository** — root contains only `codex-cli`, `codex-rs`, `docs`, `sdk`, `scripts`, `tools`, `third_party`, `patches`, `bazel`. Any IDE-extension usage panel is closed-source and `UNVERIFIED` here.

### 2.3 The layout algebra (the single most important replication detail)

`CONFIRMED` — [`codex-rs/tui/src/status/format.rs`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/status/format.rs)

```rust
pub(crate) const INDENT: &'static str = "  ";              // 2 spaces

let label_width = max(display_width(label)) over ALL labels in the card;
let value_offset = 2 /*indent*/ + label_width + 1 /*colon*/ + 2 /*gap*/;
```

- The label column is **dynamic**: it is recomputed from the labels *actually present* in that render.
- Every line = `"  "` + `label` + `":"` + spaces + value, where `spaces = 2 + (label_width − width(label))`.
- **Value column always begins at column `2 + label_width + 3`.**
- Wrapped continuation lines are indented to exactly `value_offset` (a string of that many spaces, rendered dim). If the terminal is too narrow for the label column, continuation falls back to the 2-space outer indent.

Verified arithmetic against three real snapshots:

| Snapshot | Longest label | `label_width` | `value_offset` | Observed `  Model:` + N spaces |
|---|---|---|---|---|
| `includes_credits_and_limits` | `Context window` | 14 | **19** | 11 ✓ |
| `includes_enterprise_monthly_credit_limit` | `Monthly credit limit` | 20 | **25** | 17 ✓ |
| `uses_generic_limit_labels_for_unsupported_windows` | `Secondary usage limit` | 21 | **26** | 18 ✓ |
| `shows_chatgpt_plan_without_email` | `Permissions` | 11 | **16** | 8 ✓ |

- Labels are rendered **dim**; values are default weight. Parenthesised detail (`(reasoning …, summaries …)`, `(resets …)`, `(… used / …)`) is **dim**.
- Word wrap uses `textwrap` with `WordSplitter::NoHyphenation`; long values (paths, UUIDs, socket URLs) wrap under the value column, never truncated — see `status_snapshot_remote_server.snap`:

```
  Server:          unix:///tmp/codex-home/app-server-control/app-server-
                   control.sock (v0.133.0)
```

**Critical quirk — `Token usage` is suppressed for ChatGPT subscribers.** `CONFIRMED`, [`status/card.rs#L855-L858`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/status/card.rs#L855):

```rust
// Hide token usage only for ChatGPT subscribers
if !matches!(self.account, Some(StatusAccountDisplay::ChatGpt { .. })) {
    lines.push(formatter.line("Token usage", self.token_usage_spans()));
}
```

Rationale (INFERRED): subscription users are billed by rate-limit windows, not raw tokens, so raw token totals would be noise. **This is the opposite of what a DSH token dashboard wants** — DSH has no subscription windows, so DSH should *always* show the token row.

### 2.5 Progress-bar geometry

`CONFIRMED` — [`status/rate_limits.rs#L24-L26, L369-L389`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/status/rate_limits.rs#L24)

```rust
const STATUS_LIMIT_BAR_SEGMENTS: usize = 20;
const STATUS_LIMIT_BAR_FILLED: &str = "█";   // U+2588 FULL BLOCK
const STATUS_LIMIT_BAR_EMPTY:  &str = "░";   // U+2591 LIGHT SHADE

let ratio  = (percent_remaining / 100.0).clamp(0.0, 1.0);
let filled = ((ratio * 20.0).round() as usize).min(20);
format!("[{}{}]", "█".repeat(filled), "░".repeat(20 - filled))
```

- **Total width including brackets = 22 characters.** Filled count uses **round-half-away-from-zero**, not floor.
- The bar encodes **percent REMAINING** (grows as you have more headroom). The function doc explicitly warns that passing *used* percent "will invert the bar and mislead users."
- Summary text is always `<P>% left` with **0 decimals**: `format!("{percent_remaining:.0}% left")`.
- `percent_remaining = (100.0 − percent_used).clamp(0.0, 100.0)`.
- **Narrow-terminal degradation:** if `bar + " " + summary` exceeds the value column, the bar is dropped and only `<P>% left` is kept ("keep the percentage visible rather than letting the fixed-width progress bar crowd out the reset time").

### 2.6 Limit-row label derivation

`CONFIRMED` — [`chatwidget/rate_limits.rs#L103-L146`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/chatwidget/rate_limits.rs#L103), applied through `capitalize_first` in [`status/rate_limits.rs#L259-L336`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/status/rate_limits.rs#L259).

get_limits_duration(window_minutes):
    5h      if within ±5% of      300 min
    daily   if within ±5% of    1_440 min

fallback_limit_label(is_secondary):
    primary   -> "usage"
    secondary -> "secondary usage"

limit_label_for_window(minutes, is_secondary) = get_limits_duration(...) ?? fallback_limit_label(...)

Then the row label is `capitalize_first(label) + " limit"`:

### 2.7 Reset-time formatting

`CONFIRMED` — [`status/helpers.rs#L170-L181`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/status/helpers.rs#L170) and [`clock_format.rs#L25-L31`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/clock_format.rs#L25)

```rust
format_reset_timestamp(dt, captured_at, clock_format):
    let time = dt.format(clock_format.time_format());
    if dt.date_naive() == captured_at.date_naive() { time }
    else { format!("{time} on {}", dt.format("%-d %b")) }
```

| Clock pref | `time_format()` | Same-day example | Cross-day example |
|---|---|---|---|
| 24-hour | `%H:%M` | `(resets 09:25)` | `(resets 07:08 on 7 May)` |
| 12-hour | `%-I:%M %p` | `(resets 3:14 AM)` | `(resets 7:08 AM on 7 May)` |

**It is an absolute clock time, not a relative countdown.** There is no "resets in 3h 12m" anywhere in the status card.

## 5. Formatting-rules table

| Kind | Rule | Examples | Where |
|---|---|---|---|
| **Tokens, compact (status card & statusline)** | `<1000`: integer. Else scale by 1000 and suffix `K`/`M`/`B`/`T` by magnitude. **Decimals depend on the scaled value**: `<10` → 2 dp; `<100` → 1 dp; else 0 dp. ### Threshold semantics (when warnings fire)

`CONFIRMED` — [`chatwidget/rate_limits.rs#L16-L21`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/chatwidget/rate_limits.rs#L16)

```rust
const RATE_LIMIT_WARNING_THRESHOLDS: [f64; 4] = [50.0, 75.0, 90.0, 95.0]; // % USED
const RATE_LIMIT_SWITCH_PROMPT_THRESHOLD: f64 = 90.0;                    // % USED
```

- Warning text is emitted **once per threshold crossing**, at 50/75/90/95 % **used** (i.e. 50/25/10/5 % remaining), and never at 100 %:
  > `Heads up, you have less than {remaining:.0}% of your {limit_label} limit left. Run /status for a breakdown.`
- At ≥ 90 % used on any window, a model-switch prompt appears: title `Approaching rate limits`, subtitle `Switch to {model} for lower credit usage?`, options `Switch to {model}` / `Keep current model` / `Keep current model (never show again)`.
- Rate-limit polling cadence tightens with usage: `≥99%` → 5 s, `≥90%` → 15 s, `≥75%` → 30 s, else 60 s.
- Staleness threshold for the `/status` `Warning` row: **15 minutes**.

**There is no green→yellow→red bar gradient.** If DSH wants that, it is an intentional addition, not a replication.

## 11. How to adapt this to DSH

### 11.1 Metric mapping

DSH exposes (per `@deepseek-ai/dsh-token-meter` and `@deepseek-ai/dsh-session-stats` — `CONFIRMED` from the local package references at `.reference/dsh-token-meter/README.md` and `.reference/dsh-session-stats/README.md`):

**`tokenUsage` projection** (whole durable log): `uncachedInputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`
**`contextPressure` projection**: `pressureTokens`, `projectedTokens`, `contextWindow`
**`contextBreakdown` projection**: `systemTokens`, `toolsTokens`, `messageTokens`
**`sessionStats` projection**: `turns`, `steps`, `llmMs`, `toolMs`, `ttftMs`/`ttftSteps`, `decodeMs`/`decodeTokens`
**Service**: `ctx.tokenMeter.measure(session)` → `{ totalTokens, surfaceTokens, nodes[] }`; `estimateMessage(message)`
**Capacity**: `ctx.llm.resolveModelInfo().context`
**Per-turn**: `deriveTurnTokenUsage(events)`

| Codex row | DSH equivalent | Verdict |
|---|---|---|
| `Token usage: {T} total ({I} input + {O} output)` | Define `T = uncachedInputTokens + outputTokens` (mirrors Codex's `blended_total`) and `I = uncachedInputTokens`, `O = outputTokens`. | **Keep verbatim.** This is the single most important row and the whole point of the plugin. |
| `Context window: {P}% left ({U} used / {W})` | `P = 100 − round(pressureTokens / contextWindow × 100)`; `U = projectedTokens` (better than `pressureTokens` — it answers the *next* request); `W = contextWindow` from `resolveModelInfo().context`. | **Keep, with a fix.** Do **not** copy Codex's 12 000-token baseline subtraction — that is a Codex-specific fudge for its system prompt. DSH's `pressureTokens` is already a clean prompt-side figure. |
| `5h limit` / `Weekly limit` progress bars | **No equivalent.** DSH has no rolling provider quota windows. | **Drop the bars.** Replace with DSH-native *time-window token spend* if you have history: `Today`, `Last 7 days`, `Last 30 days` as plain numbers — **do not** render them as `% left` bars, because there is no denominator. If you want a bar, use it for **context occupancy** instead, which is a real 0–100 % quantity. |
| `Credits: 25 credits` / `Unlimited` | **No equivalent.** | **Drop.** |
| `Monthly credit limit: 8,000 of 25,000 credits used` | Possibly derivable from a configured budget, but DSH has no budget concept. | **Drop**, unless the engineer adds an explicit user-set budget in Settings — in which case copy this row *exactly* (bar + dim `{used} of {limit} used` continuation). |
| `Account: user@example.com (Pro 200)` | **No equivalent** (no plan name, no account email). | **Drop** the plan. Optionally substitute the active provider/model route. |
| `Model: gpt-5.1-codex (reasoning none, summaries auto)` | Yes — model id from the adapter; reasoning effort is available. | **Keep**, reuse the `(reasoning X, summaries Y)` dim-suffix convention. |
| `Model provider: server-ollama` | Provider id if multi-provider. | **Keep** if applicable. |
| `Directory: ~/code` | Session working directory. | **Keep** if the Settings panel knows the session. |
| `Permissions: …` / `Agents.md` / `Session` / `Forked from` / `Thread name` / `Collaboration mode` / `Server` | Mostly DSH-shaped concepts exist (permissions, session id, thread name). | **Keep** the ones that map; the *pattern* is what matters — a config block above a separated usage block. |
| `Warning: limits may be stale - start new turn to refresh.` | Still useful: mark the readings stale when the log tail hasn't advanced. | **Adapt.** Rename to something like `Warning: figures may be stale - reload to refresh.` |
| `Lifetime tokens` / `Peak tokens` / `Longest chat` / `Current streak` / `Longest streak` | **All five are derivable** from a durable event log: lifetime = sum of tokenUsage; peak = max daily bucket; longest chat = max turn duration (`llmMs`/wall time); streaks = consecutive active days. | **High-value, keep all five.** These are the strongest part of the "profile panel" and map cleanly. |
| `Token activity` 12-month heatmap | Derivable from daily buckets. | **Keep** if a daily aggregate exists; glyph set `□ ■` and the `Less □ ■ ■ ■ ■ More` legend are cheap to reproduce. |
| `Total chats` | `sessionStats` gives turns/steps; a chat count needs the session index. | **Keep** if available; otherwise substitute `turns` / `steps`. |
| `Fast Mode` / `Most used reasoning` | Reasoning effort is DSH-available. | **Keep** the reasoning row; drop Fast Mode unless DSH has a fast tier. |
| `Most used plugins and skills` (`@plugin`, `$skill`, `{n} runs`) | DSH has plugins and skills. | **Keep** — the `@`/`$` prefix convention and `{n} run(s)` wording are directly reusable. |
| `Thread usage: 5.2 credits · ~$0.21` and `Models/Reasoning/Speed/Billed tokens` | Credits/USD have **no** DSH equivalent; the *breakdown percentage list* does. `deriveTurnTokenUsage` gives per-turn data, and `contextBreakdown` gives composition. | **Adapt heavily.** Keep the shape: `{Name} {pct}%` comma-joined per dimension. Substitute dimensions that exist in DSH — **Model**, **Reasoning**, and **Context composition** (`System {pct}%, Tools {pct}%, Messages {pct}%` from `contextBreakdown`) instead of Codex's Model/Reasoning/Speed. Drop the credits figure. |

### 11.2 What to copy verbatim (highest fidelity-per-effort)

1. **The two-column label card with a dynamic label column.** Compute `labelWidth = max(label lengths)` over the *rendered* rows, then place values at `2 + labelWidth + 3` (or, in CSS, use `display:grid; grid-template-columns: max-content 1fr; gap: 0 1ch` which reproduces the same "ragged but aligned" effect). Codex's dim-label/default-value contrast is the core visual signature.
2. **The blank-line section break** between the config block and the usage block.
3. **`{P}% left` phrasing, 0 decimals** — and *remaining*, not used, wherever a true denominator exists (context occupancy).
4. **Compact token formatting with the magnitude-dependent decimal rule** (`<10`→2 dp, `<100`→1 dp, else 0 dp, strip trailing zeros). Reimplement `format_tokens_compact` exactly; it produces the recognisable `1.2K` / `128.5K` / `1.2M` look and is ~20 lines.
5. **`>` dim parentheticals** for secondary detail: `(reasoning high, summaries detailed)`, `(1.2K used / 272K)`.
6. **` · ` (space-middot-space) as separator**, with the separator dimmed.
7. **`—` em dash for missing values**, and **omit-don't-blank** for unavailable items.
8. **The `Less □ ■ ■ ■ ■ More` heatmap legend** and the `□`/`■` cell pair.
9. **`▲` cursor + `─` baseline** for any bar chart.
10. **Accent `#63A8F8` dark / `#1C64C8` light.**

### 11.3 What to drop or redesign

| Codex thing | Why it doesn't transfer | Recommendation |
|---|---|---|
| 5-hour / weekly / monthly rate-limit windows | No DSH provider quota. | Drop, or replace with DSH `Today / 7d / 30d` **absolute** token counts (no `% left`, no bar). |
| Credits, `Unlimited`, `Available` | No DSH credit system. | Drop. |
| Monthly credit limit row | No budget concept. | Drop, or make it an opt-in user-set budget in Settings. |
| Plan name (`Pro 200`, `Business`, `Education`) | DSH has no subscription plan. | Drop. If a heading is needed, use the provider/model route. |
| `Account: email (Plan)` | No account identity in a local harness. | Drop, or substitute the provider id. |
| 12 000-token context baseline | Codex-specific constant for its own system prompt. | **Do not port.** Use raw `pressureTokens / contextWindow`. |
| Hiding the token row for subscription accounts | Inverted for DSH. | Always show tokens. |
| `Warning: limits may be stale` wording | Refers to rate limits. | Reword to "figures may be stale". |
| 20-cell `█`/`░` bar for **rate limits** | Meaningless without a denominator. | **Repurpose** the identical bar component for **context occupancy** — that is a genuine 0–100 % remaining quantity and the bar is a perfect fit. |
| Absolute `(resets 09:25)` times | No reset events. | Replace with `(updated 09:25)` for the data-freshness stamp, keeping the exact same formatting function. |
| `/usage` full-screen TUI dashboard | DSH Settings is a web panel, not an alternate-screen TUI. | Port the *content model* (tabbed Overview / Tokens / breakdown), not the alternate-screen navigation. Map the key hints (`r`, `g`, `m`, `z`, `R`, `?`) onto visible toolbar controls, since a web panel has no modal keymap. |
